# Guarded Auto refinement: independent rejection gates

Recorded October 15, 2026 at 07:43 UTC, before `bench/auto-refinement-spike/results.json` existed. This reviewer owns no production changes. These gates precede candidate rankings; passing an average-error comparison alone does not authorize shipping.

## Current contract and initial recommendation

The actual pipeline captures the whole wall in `palette-generated-sources.js`, produces one shared target of at most 64 RGB colors in `palette-generated.js`, then selects an exact subset separately per asset in `palette-limit.js`. A GIF is one asset: all frames contribute with duration weights and use one subset. Nonempty assets contribute equal normalized mass to Auto, independently of dimensions, frame count or wall order. An empty wall uses the example; an all-transparent real wall remains authoritative. Keep uses eligibility cut 1, while Cut uses the captured cutoff.

`fullPaletteImage` resolves the captured generated target before applying the cap, Cleanup and dithering. The displayed target, imported/reused colors, snapshots, count metadata and encoded files rely on that same target identity. Generation currently does not depend on Matching, cap, Cleanup or dither settings. Exact target/subset RGB members stay exact during conversion.

**Initial recommendation:** a per-asset centroid refinement that invents RGB colors outside the shared target is a different capability, even when its point-error guard succeeds. Do not insert it silently into existing Auto/Max colors. Research it explicitly as a separate fitting contract, or investigate a genuinely shared wall refinement that preserves the current target/cap relationship. No new control is approved by this review.

## Rejection gates

| Gate | Required evidence and rejection condition |
|---|---|
| Scope and target identity | Record the shared target, selected subset and actual visible output RGBs for each asset/frame. Existing Auto must remain one shared target; every per-asset subset/output RGB must belong to it. New per-asset centroid colors fail this semantic gate regardless of score. A separate shared K-color wall budget also changes existing per-asset semantics. |
| Unchanged paths | Fixed authored/imported palettes, legacy 1-bit, cap All and cases where the current subset already represents the source exactly must retain their existing behavior. A proposal that deliberately changes any of these must name it separately rather than count it as an invisible optimization. |
| Objective and verification | Compare rounded/gamut-clamped candidate RGBs against the actual selected baseline, using the captured matching metric and source/frame weights. Adopt only a finite strict improvement greater than numerical tolerance; ties retain the baseline. Verify against original eligible pixels, not only histogram-bin means or a training approximation. Publish every accepted/rejected case, both metrics and all baseline costs. |
| Exact and rare details | Count changed pixels that previously reproduced source RGB exactly; any new loss rejects silent adoption. Retain exact and muted one-pixel eye/outline/material-accent fixtures against a much larger shaded body. Measure every source-RGB group's error, rare-region output/contrast and native-size appearance separately. A lower mean, or even nonincreasing per-RGB distance, does not establish preserved hue, outlines or artist preference. A visible lost or false detail rejects the candidate for general replacement. |
| Actual downstream rendering | Exercise actual preparation and conversion, not a nearest-only surrogate. Include Oklab/RGB; Cleanup Off/On with marked source coordinates inspected; dithering Off, each 2×2/4×4/8×8 matrix, strength zero/default/maximum on selected counterexamples. Publish point distortion and block-tone measurements separately. Nearest improvement cannot authorize changed Cleanup decisions or worse dithering by inference. |
| Alpha and geometry | Preserve source dimensions and the existing sampled source-center coordinates. Test alpha 0/1/127/128/254/255 under Cut and Keep, including all-transparent and mixed-opacity sources. RGB fitting must not change alpha bytes/visibility, create hidden RGB influences or silently add opacity weighting. Partial-alpha PNG and explicit partial-alpha GIF rejection retain their current contracts. |
| Animation | Fit once across all frames, retain duration weighting, delays and loop metadata, and never refit independently per frame. Check two nearly identical frames for changed output at unchanged coordinates, with palette/settings fixed. Dither phase stays source-anchored. Distinguish unavoidable global fitting changes after source edits from a temporal guarantee. |
| Preview/export/inspection | The same immutable captured result must reach sampled wall previews, full Preview, Count/Use, PNG, GIF, ZIP, Copy and drag. Check export after an immediate settings/source change and no stale result after cancellation. No preview-only refinement or encoder-side second fit. |
| Determinism and lifecycle | Reorder the wall, split source chunks differently, repeat jobs and compare target/output bytes. Exercise queued and running cancellation, last-subscriber cancellation, shared consumers, malformed worker output and worker-unavailable fallback. Fail closed on refinement errors; no silent unguarded or stale result. No source mutation/detachment. |
| Bounded work and performance | State fixed limits on histogram storage, iterations, source passes and retained buffers. No unbounded RGB dictionary or retained converted animation. Measure cold preparation and warm repeated cap/export gestures separately, with interleaved baseline/candidate cases in foreground Codex Browser and the physical Android device. Report raw timings and task support/scope; do not infer phone speed from Node medians. New observed >50 ms main-thread tasks, broken cancellation, growing memory or repeated unnecessary source fits reject production adoption pending a specific repair. A measurable sustained latency regression also needs an explicit product tradeoff, not an automatic average-quality approval. |

The objective tolerance is `1e-12 * max(1, abs(baselineMeanCost))` on the stated metric's mean squared distance. It is a numerical comparison allowance, not permission to hide visible changes. Exact RGB/alpha/identity assertions have no tolerance. Screenshot resampling at pie edges is unrelated to these conversion assertions.

## Comparison discipline

Use the same owned source bytes, alpha eligibility, dimensions and intended count/scope for current, candidate and retained service outputs. A service-generated K-color image and the app's subset of shared Auto64 answer different questions unless that difference is explicitly retained. Compare fixed targets only when their actual RGB values match. Native dither strengths have different scales; show their presets without pretending 5 equals 50 or selecting one favorable strength as a universal result. Preserve adverse cases and untested cells.

The previous [fitting study](2026-10-14-auto-fitting-and-color-locks.md) is a prerequisite, not evidence that the new candidate passes: its direct fit worsened four of twenty equal-scope cases, and the armor K4 figure lost a warm material cue. The new initialized refinement must retain those rejection fixtures. No new paid service request is needed for independent methodology review.

## Independent guard challenge

The [independent executable](../../bench/auto-refinement-spike/independent-guard-check.mjs) and [retained result](../../bench/auto-refinement-spike/independent-guard-results.json) exercise the research candidate directly and use production quantization plus independently calculated point errors to inspect actual pixels. This synthetic test deliberately supplies its own black/white seed; it is a guard contract counterexample, not a claim that the current Auto pipeline would choose that seed for this image.

One 32×32 source contains 1,023 mid-gray pixels and one exact white highlight. Mean-only centroid refinement moves white to gray, reducing Oklab error from approximately 0.159947 to 0.00015635 while deleting the only white highlight. The RGB metric shows the same failure. Strict and rare guards retain the original seed. A positive control adds gray to the published shared target: the strict target-preserving swap selects gray plus white and reaches zero error, demonstrating that the test can accept a safe improvement rather than always retaining the baseline.

Both metrics also pass hidden-alpha-zero RGB invariance, Keep's preservation of an alpha-one exact highlight during fitting eligibility, frame-duration splitting invariance, zero-pass baseline retention, exact-source overflow fallback with a null incomplete objective, and source immutability. Pre-canceled and in-flight work reject with AbortError. The retained Node in-flight check took approximately 19.3 ms including its final source-hash check; this is not a browser or physical-device latency claim.

During source review, two reporting/guard issues were raised and corrected before final runs: a strict-less-than comparison could accept numerical-noise changes rather than a meaningful improvement; and a truncated overflow histogram was divided by the full source mass, making its reported baseline error incomplete. The candidate now applies the declared mean-improvement tolerance and reports incomplete overflow objectives as null while retaining the baseline.

## Broader research and device reconciliation

The reviewer inspected the broader [research runner](../../bench/auto-refinement-spike/run.mjs) and independently recomputed summaries from its [retained results](../../bench/auto-refinement-spike/results.json). It covers 176 source/scope/count/metric/opacity cases, including rare exact/muted eyes, an outline/material stripe, nearby critical hues, saturated colors, 6,144 unique RGBs, a four-asset wall and two weighted animations. These are structured counterexamples plus two artwork sources, not 176 independent artist examples.

Mean centroid refinement changes 175 cases and leaves the shared target in all 175. Mean-only subset swaps improve six means but can worsen as many as 246 source-RGB groups. Strict and rare policies change zero cases for both methods. The independent gray/highlight positive control above remains important: it shows that strict target-preserving swaps can accept a safe improvement, even though this current-pipeline cohort provides none.

The seven focal configurations produce 140 actual Cleanup/dither settings comparisons. Every changed variant in these comparisons has lower point error, but 26 rows have worse measured 4×4 tone error; repeated zero-strength controls are included in that count. Mean-centroid changes also alter Cleanup's marked-site mask at eleven inventory coordinates and two armor coordinates. The recorded site-change field compares marked/unmarked membership; it does not measure every replacement RGB change at still-marked coordinates. Point and tone metrics have separate scopes, and eligible/excluded block counts remain in the artifacts. No alpha mismatch or unchanged-coordinate animation churn is reported in these bounded interaction checks. Seven focal PNG encode/Sharp-decode checks use strict palettes, which are unchanged baselines here; they are not proof of newly accepted candidate exports.

The final [Codex Browser report](../../bench/auto-refinement-device-review/codex-results.json) and [physical Android report](../../bench/auto-refinement-device-review/android-results.json) each complete 24 method/case checks with no reported errors. The reviewer inspected the [HTML harness](../../bench/auto-refinement-device-qa.html) and [loopback server](../../bench/auto-refinement-device-server.mjs), then independently checked both reports' seven module hashes and fixture hash against disk and one another. Candidate SHA256 is `2bf68423c4c4ece2d3ca38ad3ada00f32d8ec6491a1545c1dad99d4fa39e4e77`, matching the independent and paired research.

All 24 strict candidates retain baseline colors and identical RGBA hashes on each device. Actual rendering verifies alpha, dimensions, target membership, frame count, original delays/loop and exact baseline pixels. Repeat fitting is deterministic; the tested downstream settings do not worsen because the strict palettes are unchanged. This is not evidence that a novel accepted palette preserves these properties in the app. The harness imports research kernels and production conversion modules; it does not install the candidate into Auto UI/workers/caches or verify encoded candidate downloads.

The bounded cost source contains 32,768 pixels with 4,096 unique RGBs, so refinement is exercised within its exact histogram bound rather than timing only overflow fallback. Alternating-order runs retain one warmup and three measured samples. Median subset selection rises from 24.9 to 91.0 ms in Codex Browser and 26.8 to 65.1 ms on the phone when this all-three-policy research search is added. Samples are noisy and exclude decoding, worker transfers, Auto generation, warm production cache reuse and UI; do not convert these numbers into a shipping speed ratio or a single-policy estimate. They establish additional work without a measured adopted quality gain in this cohort.

Pre-cancellation and in-flight cancellation reject with AbortError; observed in-flight durations are approximately 9.1 ms desktop and 8.3 ms phone. Supported long-task observers record three tasks in the desktop run and six on the phone over the entire research harness, including independent synchronous scoring, rendering and JSON updates. They cannot be attributed to the candidate alone or called production UI regressions. Conversely, these records cannot support a blanket no-long-tasks claim.

## Final recommendation

**Do not ship either candidate as a default optimization.** Mean-only centroids fail target identity, exact/rare-detail and downstream tone gates. Mean-only target-preserving swaps can trade away source-color fidelity. The strict/rare variants retain the baseline throughout the current-pipeline cohort while adding preparation cost. The tested candidate therefore fails the user's improvement-without-regressions condition; leaving production unchanged is the supported outcome.

Keep the current Auto/Max colors behavior and existing Count/Use workflow. Retain these adverse fixtures before another algorithm experiment. Any future proposal should first declare whether it refines the shared wall target, selects its subset, or deliberately offers a different per-image fitting mode. It must then demonstrate accepted improvements under exact/rare-detail and downstream gates before production integration or new controls are justified. A color lock remains a separate product contract: keeping a target RGB available is not forcing a semantic region to use it. No lock control or additional count row is justified by this result.

No production files were edited by this reviewer or by the research candidate. Broader production regression runs are unnecessary for the unchanged app; deployment, Safari, all possible art preferences, custom picker HSV/Cancel and general service endpoint equivalence remain outside these bounded findings.
