# Palette improvements: independent adversarial review

October 14–15, 2026. Review scope: the compact preset additions, public palette-link import, explicit full-source color inspection, output-palette reuse, Palette Keep/Cut opacity and color-critical full-palette controls under browser forced darkening. Production changes were made by their assigned owners. This reviewer inspected their changes, challenged contracts, ran focused checks and added a separate browser harness; the reviewer did not edit production files.

The feature implementation is represented by commits `884afbf`, `9ab4dcf`, `33dfb37`, `a825fcb`, `ba357c3`, the caption follow-up `e5b5b5a` and the canvas control fix `e3710e4`. The tested production index hash is recorded below. Final independent browser checks were completed October 15. No outstanding actionable production defect was identified in the bounded review described below. This is not a claim that every image, device or failure mode has been verified.

## Concrete findings and resolutions

The count-key, range-ownership and caption findings were raised during this independent review and fixed by the owners. The import ownership behavior was reviewed and independently challenged in the completed integration.

**Color-critical controls.** The canvas helpers validate every opaque HEX entry, including entries omitted from the existing sixteen-color overview, before touching the current canvas. Svelte action updates repaint changes. The one-pixel solid and 100×100 overview paintings perform no readback, image encoding, SVG generation, object-URL management or network requests. The overview retains its existing selected colors and order, drawing clockwise sectors over an opaque first-color underpaint. Existing button labels, pressed states, keyboard actions and native color-input elements remain responsible for semantics. The input overlays have `pointer-events: none`; their underlying input remains the center hit target. This is a display-only correction: artwork conversion, snapshots and export encoders are untouched. The separate legacy 1-bit preview branch is unchanged.

## Reviewed contracts

**Color inspection and reuse.** The new action is explicit; rendering the wall or hovering an image does not start a separate full-resolution count. It calls the actual full-palette export conversion, visits every animation frame sequentially, unions final used RGB labels after Cleanup, excludes empty pixels and retains target order. It keeps only a small frozen color list/count, not a converted clip. Fixed-palette all-transparent input returns zero colors; reuse is unavailable for that result. Auto's no-visible-colors condition remains distinct from an invented one-color palette.

The app keys each result to its current immutable item and conversion snapshot, cancels obsolete work on settings/family/removal changes and prevents an old completion from publishing over a newer owner. Count errors remain metadata errors rather than being registered as failed recoloring that disables otherwise valid Save. The reuse action opens the existing palette editor as a new draft; Save or HEX backup remains the user's next action. Reapplying that palette with different settings or artwork is not promised to reproduce the former output exactly. The initial batch intentionally does not seed the count cache from exports; Count followed by Save can convert the source again, while avoiding retained full-frame memory.

**Keep/Cut opacity.** Cut at 128 remains the default and reset behavior. Keep includes every source pixel with alpha greater than zero in preparation, remaps its uncomposited RGB and preserves its exact source alpha. It does not introduce alpha-weighted palette fitting or choose a compositing background. Nearest and every enabled ordered matrix use the same source-center sample coordinates. Cleanup changes labels without changing alpha. Full-source snapshots, source preparation, preview identities and the animation cache carry the mode; cached Keep samples reserve one extra byte per pixel within the existing budget.

Actual partial opacity forces direct RGBA8 PNG output. Binary Keep input retains the existing indexed PNG/GIF bytes. GIF cannot represent partial opacity: both preflight and encoding check frame alpha, and partial alpha rejects explicitly before a download; no silent conversion to Cut is introduced. Ordinary decoded GIF source frames already use binary alpha.

**Presets and palette links.** The additions preserve previous IDs, RGB values, relative order and defaults. Black & white supplies fixed pure endpoints in Palette; ENDESGA 8 supplies a fixed broad-hue eight-color target. They are convenience choices, not measured universal quality improvements. The [curation study](2026-10-14-curated-palette-selection.md) retains the poor armor result and small corpus limitations. The public link importer uses a canonical fixed-origin endpoint, no credentials/referrer, no redirects, a streamed 64 KiB bound and a 15-second deadline. It retains current colors until a complete valid replacement is available; stored source links must pass the same canonical validation.

3. Reset invalidates a count whose optional module is still pending.

6. Completing a held shared Auto refresh preserves the count that was requested against it.
7. 9. The same checks pass at short landscape 568×320.

## Cross-device evidence and performance review

The reviewer inspected the separate [Codex Browser](../../bench/palette-improvements-review/codex-results.json) and [USB Android](../../bench/palette-improvements-review/android-results.json) acceptance reports and their [HTML harness](../../bench/palette-improvements-qa.html). Both contain 15 completed checks with no reported runtime errors, including actual live public-palette import, final whole-GIF RGB union, exact output-palette draft/HEX backup, persistence, captured exports after immediate setting changes and preview/PNG/GIF/ZIP alpha checks. The harness independently decodes encoded payloads while comparing expected recoloring against the production conversion modules; the recoloring oracle itself is not a separately implemented algorithm.

Those checks intercept download anchors and clipboard writes to inspect actual encoded blobs. They establish payload correctness, rather than operating-system clipboard or filesystem delivery. Root separately pulled a real Android Downloads PNG: the [receipt](../../bench/palette-improvements-review/android-native-save.json) and [native file](../../bench/palette-improvements-review/android-native-keep.png) record 1,912 bytes and SHA256 `af55fff6eab37b18e9020222f792ed60bc87010a2665daeb063811b236409388`. This reviewer independently decoded that file and the harness's original generated ramp with Sharp, compared all 8,192 source alpha bytes exactly, and confirmed 128×64 dimensions, six visible RGB colors and alpha values 0/127/128/255. This closes the native file-delivery check for that PNG; it does not establish OS clipboard success.

The refreshed reports explicitly identify supported long-task observers and observed no long tasks in their recorded scopes. Their separate 256×128 source-kernel cases retain three warm timings per mode, progress intervals and frame-gap observations. Binary Keep/Cut cases have identical visible workloads; partial Keep includes 28,672 pixels while Cut includes 16,384, so their runtime difference cannot be attributed solely to alpha-buffer overhead. Desktop timings varied substantially between runs and must not be described as a causal Keep speedup. The exact memory contract is one additional alpha byte per converted Keep sample, with RGBA export rows needed for partial PNG opacity; retained preview memory fields do not represent total process/GPU/source/preparation memory. These measurements establish bounded behavior in these runs, not FPS or a general performance guarantee.

## Research decision challenge and limits

The [Auto-fitting and locks study](2026-10-14-auto-fitting-and-color-locks.md) was independently checked against its retained calculations and native/enlarged armor figure. Direct fitting improves point error in 16 of 20 equal-scope single-asset/GIF cases, with the four disclosed regressions recomputing to approximately 5.0%, 9.0%, 10.4% and 6.3%. The separate shared-subset control correctly avoids confusing a shared K-color wall budget with today's per-asset cap. The armor K4 figure supports the report's limited observation that a warmer material accent is lost. The one-pixel lock counterexamples correctly distinguish target availability from actual use. These support further research and the decision to defer changing shipping algorithms or adding lock controls; they do not establish artist preference, optimal fitting or phone speedups.

The independent lifecycle checks use synthetic responses; only the separate owner acceptance records exercise the live catalog. The layout checks cover the stated widths and controls, not every translation, font size, virtual keyboard or browser. Long clips, large walls and varied device loads can differ. Safari/iOS and operating-system clipboard delivery remain unverified. No unresolved actionable defect was found in the inspected implementation after the recorded fixes, within these explicit limits.
