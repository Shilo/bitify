# Direct palette feature and output comparison

Date: October 14, 2026. This is a service-specific comparison, separate from the four neutral improvement spikes. Public documentation was refreshed for this follow-up. It combines measured outputs, observed website controls, public schemas and the already inspected installed editor extension; it makes no claim about service implementation internals.

Colorfetti should keep its local, immediate fixed-palette workflow. The most useful next additions after ordered dithering are precise used-color feedback, explicit low-count Auto fitting, palette reuse/export, artist-directed color protection and an optional shared subset across related assets. More presets and more pattern sizes should earn their place through distinct useful results. Image generation, cloud asset management and semantic recoloring are different product scopes, rather than a checklist Colorfetti must duplicate.

## Evidence key and sources

**R** means an operation/output was tested; **UI** means the website affordance or acquisition was observed, without verified generated output; **D** means current public documentation/schema; **S** means installed extension static inspection; **—** means not found in that inspected interface, rather than proven absent everywhere. A successful test establishes the tested case, not every input.

The official [reducer guide](https://www.pixellab.ai/docs/tools/reduce-colors), [color options](https://www.pixellab.ai/docs/options/color), [dither options](https://www.pixellab.ai/docs/options/dithering), [REST schema](https://api.pixellab.ai/v2/openapi.json), [REST endpoint index](https://api.pixellab.ai/v2/llms.txt) and [MCP guide](https://api.pixellab.ai/mcp/docs) were refreshed. Runtime records are the [API/MCP report](api-mcp-evidence.md), [website closure](coverage-closure.md) and new workbench evidence linked below. The [extension inventory](extension-palette-evidence.md) records local-copy/version limitations; it is not proof of an unmodified vendor release or working editor runtime.

## Additional live workbench tests

Five bounded workbench commands were run: help, snap repair, extraction, ramp generation and stray repair. The live tool description calls these free for subscribers; no reducer or generation endpoint was invoked by this follow-up. No account balance delta was measured, so billing is described by the contract rather than inferred from missing usage fields.

The owned 16×16 fixture has four RGB values, 22 alpha-zero pixels, 36 alpha-127 pixels and 198 opaque pixels. `repair --ops snap` reported zero changes and returned byte-identical decoded RGBA. This establishes a working no-op; it supplies no fixed target and does not prove arbitrary target snapping. `repair --ops stray` removed the opaque pixel at (15,8), preserving RGB everywhere else and the remaining partial alpha. Colorfetti with these same four exact target RGB values and Cleanup On retained all opaque coordinates; its cut 128 intentionally makes the 36 partial pixels empty. Common opaque coordinates have zero RGB disagreement. Thus the tools have different alpha/geometry contracts, not a demonstrated quality winner.

Extraction returned the four correct RGB entries, one gray ramp and separate translucent entries. Named four-step skin and wood ramps returned eight text colors. Their annotated swatch PNGs contain 79 and 112 visible RGB colors respectively because labels, antialiasing and background are included. These presentation images are **not clean raw palette strips**. Import the text values or an explicit clean strip; blindly extracting every color from an annotated swatch sheet is a real reuse trap in either workflow.

Reproduction: `node bench/palette-service-research/api-workbench-followup.mjs` and its `more` variant call the free subscriber interface using the environment credential. `node bench/palette-service-research/api-workbench-followup-analyze.mjs` is offline. See [requests/results](../../../bench/palette-service-research/api-workbench-followup-results.json), [extraction/ramp/stray results](../../../bench/palette-service-research/api-workbench-followup-more-results.json) and [independent pixel analysis](../../../bench/palette-service-research/api-workbench-followup-analysis.json). ## Product priorities and tradeoffs

| Priority | Concrete improvement | Benefit and acceptance condition | Tradeoff |
| --- | --- | --- | --- |
| Now | Clear ordered-dither controls and paired sprite review | Full dimensions 2×2/4×4/8×8, Off default, explicit Dither strength, source-coordinate/export agreement | Added texture can harm tiny details or increase file size |
| Next | Actual used RGB count and quick budgets | Separate target size, requested maximum and output usage; transparency wording explicit | GIF/set summary scope and asynchronous status need care |
| Next | Explicit “fit Auto to K” operation | Fit desired compact source palette directly; preserve shared asset/frame weighting and cancellation | Different intent from capping a fixed target; no silent target-color mutation |
| Next | Save used palette / reference-image snapshot / clean export | Reuse a result with exact RGB/order and clear frame scope; avoid annotated-image color pollution | Unused target colors and current output colors must remain distinct |
| Next | Target locks and exact source→target overrides | Protect deliberate eye/highlight/accent colors within feasible cap | More artist control costs UI complexity and may increase global pixel error |
| Later | Whole-set cap scope | One shared subset for selected related assets, with atomic exports | Per-image fidelity can decline; weighting/scope must be explicit |
| Selective | One chromatic eight-color preset and optional catalog acquisition | Distinct hue coverage, attribution, exact definitions and browser-origin test | Import already works; rail expansion without useful differentiation adds noise |
| Research | Ramp grouping/editing, alpha-preserving mode, targeted geometry repair | Artist evidence and explicit contracts before UI work | Broadens product and codec/animation semantics; not justified by a single competitor output |

Keep the Oklab nearest default. A better averaged-tone score is not automatically better sprite readability, and preserving exact RGB does not preserve semantic color roles if the target lacks useful hues. Smart generation, retouching and deterministic fixed-target recoloring need different evaluations. No result here justifies promising Colorfetti will always look better.

## Paired output audit

The [paired harness](../../../bench/palette-paired-comparison/run.mjs) replays 25 retained successful reducer cases and 12 additional bounded requests, including unchanged native 64×64 item art and a 16×16 armor sprite already in the repository. The 12 new reductions all succeeded and reported 1.2 subscription generations, bringing confirmed reported research use to 13.8 including the original Pro test; the separate Pro USD field and unknown website billing are not converted or added as generations. The [manifest](../../../bench/palette-paired-comparison/manifest.json) records source PNG hashes and explicit target inputs. These new real-art inputs are distinct from the original synthetic-only cohort. The [full results](../../../bench/palette-paired-comparison/results.json) retain Oklab and RGB variants, Off controls, native dither defaults/maxima, alpha checks, temporal comparisons and 115 independently decoded production PNG round trips. The review independently checked the retained hashes against all six current production engine files. Native strength 5 versus 50 and maxima 10 versus 100 are each product's settings, **not calibrated equal effects**.

See [sheet 2](../../../bench/palette-paired-comparison/contact-sheet-2.png) for the armor counterexample and [the complete gallery](../../../bench/palette-paired-comparison/contact-sheet.html) for labeled controls. The contact sheets use nearest-neighbor display; no source resize/blur is introduced before conversion. These are reviewer observations, not blind artist preference ratings.

The uncapped default Auto64 All variant preserves all 64 source grays with zero error; that larger palette should not be compared to the service's 34-color choice as equal capacity. The [fourth sheet](../../../bench/palette-paired-comparison/contact-sheet-4.png) also shows actual palette-image import: Colorfetti excludes the alpha-zero entry and uses three RGB values, whereas the controlled explicit-target variant supplies all four RGBs to match the service. This separately published import result is a contract difference, not a fixed-target matching regression.

Alpha differences are reported separately: the service retains partial alpha while Colorfetti applies cut 128. Point comparisons use coordinates above that cut in both source and output; block comparisons reject an entire block if any coordinate is below-cut. This prevents changed silhouettes from improving tone scores, but heavily underrepresents borders and tiny details. Raw alpha preservation cannot be claimed for Colorfetti.

PNG file sizes have two different meanings. Native files include encoder, indexed/RGBA representation and compression choices. A common RGBA encoder removes those representation differences; it still includes genuine pixel and alpha differences, so it isolates texture only where alpha/geometry are equal. Never attribute a smaller native PNG solely to a better dither pattern. The fixed-target membership and exact-color invariants are stronger evidence than any one aggregate error score.

## Dithering wording decision

The compact mutually exclusive group **Off / 2×2 / 4×4 / 8×8** is reasonable on a phone. The multiplication sign and both dimensions must remain visible; bare 2/4/8 could mean color counts. “Dither strength” is clearer than “Amount.” Help should explain that dimensions describe the repeating pattern in source pixels, while strength controls the mix effect and zero keeps nearest colors. An additional On/Off row plus a separate size row offers no demonstrated advantage for four choices.

Do not add 1×1 as a false extra method: one cell cannot distribute two colors spatially, so it duplicates the undithered result. Odd matrix sizes are possible with a different ranked pattern, but they do not follow this recursive matrix family and have no demonstrated artistic benefit in the current evidence. Offer them only after a distinct useful outcome and stable preview/export implementation is shown. Larger matrices provide more realizable coverage steps, not universal improvement.

## Remaining evidence limits

The website still has no attributable generated export despite authenticated controls and two later bounded attempts. Broad artist preference, arbitrary smart superiority, editor runtime, every repair operation, Safari, prolonged sessions and object-relative motion stability remain unverified. The service's internal quantizer, color metric and semantic algorithm are unknown. The paired output cohort must retain all variants and report point error, integrated tone, alpha/geometry, details, temporal behavior and size separately; pooling them into one “winner” would conceal useful tradeoffs.
