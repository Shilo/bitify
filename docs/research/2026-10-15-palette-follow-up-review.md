### Trusted pointer dismissal versus native file delivery

The root's actual Codex Browser Save attempt with Recolor open initially only closed the panel; its next attempt with the panel closed downloaded successfully. The [existing specification](../superpowers/specs/2026-10-06-colorfetti-app-design.md) explicitly requires that an outside press closes one panel without activating the pressed control (lines 404–412). [Dock's capture handlers](../../src/Dock.svelte) prevent both that pointerdown and its following pointer click. Programmatic `node.click()` lacks the originating press and therefore does not exercise this dismissal contract.

The new test uses exactly one trusted `page.mouse.click` for the initial press, with Recolor's expanded state asserted immediately before it. The retained trace records trusted pointerdown/click with `defaultPrevented: true`, panel closure and zero download-anchor attempts/events during 300 ms. A locator-based initial probe did not isolate that same panel-open press reliably; it was replaced with this explicit single-pointer sequence before drawing a conclusion.

With the panel then closed, a trusted Save produces a real browser download. The [retained PNG](../../bench/palette-follow-up-review/trusted-save.png) is 1,912 bytes, 128×64, SHA256 `af55fff6eab37b18e9020222f792ed60bc87010a2665daeb063811b236409388`. Independent Sharp decoding matches all 8,192 alpha bytes directly to the original ramp, and every visible RGB to the actual Keep/cap8/Cleanup/4×4 conversion. The anchor observer forwards the original implementation; it does not replace browser delivery with a captured Blob. The file is obtained through Playwright's real download event/path, rather than claiming this Edge context wrote to the user's Downloads folder. Native Save tests should close Recolor first, or deliberately verify dismissal before a second click.

The separate [kernel boundary harness](../../bench/palette-follow-up-edge-qa.mjs) and [retained receipt](../../bench/palette-follow-up-review/edge-contract-results.json) report 32 combined cases: one/256-entry targets, Cut/Keep, four ordered choices and Cleanup Off/On. This reviewer inspected the executable and receipt: its two different frames each use 192 grayscale entries under Cut while their full GIF union uses 256, so union validation cannot pass merely by counting the first frame. It independently decodes 64 PNG frames with Sharp, checks sampled/full coordinates, reuses 64 warm cache frames and releases all 32 reservations. Eight all-transparent fixed cases return zero; all-transparent Auto retains its explicit no-visible-colors failure. The exact-member/single-color fixture does not create meaningful multicolor Cleanup replacements or assess dithering quality; no GIF-container claim follows from PNG frame checks. These are complementary DOM-free boundaries, not 32 independent artwork examples. Root and the integration reviewer own their fresh full-app/unit/device records in the [current checklist](2026-10-15-palette-follow-up-checklist.md).

## Test-cleanup review

The [common acceptance HTML](../../bench/palette-improvements-qa.html) adds a sixteenth phase that deletes only the palette created by that run. It retains the actual saved ID, uses a unique run name, verifies that ID/name before opening the editor, confirms editor ownership, then invokes the normal saved-palette Delete workflow. Afterwards it requires that ID to be absent, selection to move away from it and the entire ordered array of unrelated records to equal its immediately preceding snapshot. It does not delete by a broad name pattern, restore an old whole-library snapshot or clear the library. The QA server's fresh preload resets settings only; it does not clear saved palettes.

This is a test-harness cleanup improvement, not a production deletion change. The successful-run phase does not promise automatic cleanup after an earlier failed test or protect against all possible concurrent user edits. A failed run's owned identity remains in its report for deliberate inspection. No additional production patch is warranted by that limitation.

The first device attempt exposed a test sequencing mistake: the harness clicked Delete confirmation before Svelte rendered it. The current code awaits the actual confirmation control. This reviewer inspected that correction and the [independent mobile-sized Edge receipt](../../bench/palette-follow-up-review/edge-cleanup-results.json): all sixteen phases complete, and one deliberately seeded unrelated palette survives unchanged. Its optional live Lospec phase was not requested, so this cleanup receipt alone is not a live-network result. The [host summary](../../bench/palette-follow-up-review/host-summary.json) separately records the fresh nine-phase Edge run, baseline and units, including explicit GC-worker execution of the two normally skipped tests.
